# REVIEW.md

Defects found in the starter `app/main.py` (helpers and endpoints), with how each is
noticed and how it was fixed. Line references are to the original starter file.

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `compute_late_minutes` | Uses `punch_in.replace(hour,minute,...)` for shift start, so the "shift start" rides on the punch-in's own date/offset and ignores the record's IST attendance date. Also uses `minutes > 10`, which makes 10 "not late" but 11 "late" counted from shift start — subtly off at the boundary and never anchored to IST. | Punch in at 09:40:01 IST on a 09:30 shift: starter returns a wrong value; R2 says 10. Overnight shifts are completely wrong. | Rewrote to build the shift-start instant on the record's IST attendance date (`shift_start_instant_utc`) and apply R2 exactly: not late when `delta <= 600s`, else `floor(delta/60)`. |
| 2 | `compute_overtime` | Builds `datetime.fromisoformat(date_str).replace(..., tzinfo=IST)` but compares it to `punch_out`, which PyMongo returns as a **naive UTC** datetime — mixing an aware-IST value with a naive one. It also drops the R3 "only if >= 30" rule (returns any positive minutes) and never handles overnight shifts (end is on the next day). | Overtime of 5 minutes is credited (sample #1 expects 0); any overnight shift raises or mis-computes. Comparing aware and naive datetimes raises `TypeError`. | Rewrote as `compute_overtime_minutes` using `shift_end_instant_utc` (adds a day for overnight shifts), a single naive-UTC clock, floor minutes, and the `>= 30` gate. |
| 3 | `compute_work_hours` | Uses Python's built-in `round`, which is banker's rounding on a float — not decimal half-up (R4). | 8.425 -> `round` gives 8.42, R4 requires 8.43. Fails exact-boundary comparisons. | Added `half_up()` using `Decimal(..).quantize(ROUND_HALF_UP)` and use it for work hours and all reported rates. |
| 4 | `create_employee` | Check-then-insert (`find_one` then `insert_one`) with no unique index. Two concurrent creates both pass the check and both insert — duplicate `emp_code`. No field validation (any string accepted). | Fire two identical creates in parallel: both return 201. `emp_code` "BAD" or a bad email is accepted. | Dropped the pre-check; created a unique index on `emp_code` and catch `DuplicateKeyError` -> 409. Added a Pydantic model enforcing the contract patterns and "shifts differ". |
| 5 | `create_employee` | `created_at = datetime.now()` is naive **local** time, so stored instants are in the server's local zone, not UTC. The returned document is the raw insert (includes the just-set `_id` risk) and `created_at` is a datetime, not epoch ms. | On a non-UTC host, `created_at` epoch ms is off by the local offset. Response shape is wrong. | `now_utc_truncated()` (naive UTC, whole seconds). Response goes through `serialize_employee`, returning `created_at` as epoch ms and never `_id`. |
| 6 | `list_employees` | `skip = page * page_size` — page 1 skips the first page entirely (off-by-one; R10 says offset is `(page-1)*page_size`). `total = count_documents({})` ignores the department filter. No sort. Returns Mongo docs with datetimes, not epoch ms. | `GET /employees?page=1` drops the first `page_size` rows. `total` with a `department` filter still reports the whole collection. Order is non-deterministic. | Offset `(page-1)*page_size`; `count_documents(q)` with the same filter; `.sort("emp_code", ASCENDING)`; serialize each row. Added `page>=1`, `1<=page_size<=100` validation. |
| 7 | `punch_in` | Never checks the employee exists, then does `emp["shift_start"]` — `None` subscript raises a 500 for an unknown employee instead of 404. | `POST /attendance/punch-in` for a non-existent `emp_code` returns 500. | Look up the employee first; 404 if missing. |
| 8 | `punch_in` | `datetime.fromtimestamp(body.punched_at/1000)` is naive local time, and `/1000` keeps microseconds (no R1 truncation). The attendance date is `ts.date()` in local time, not the IST date, and ignores overnight shifts (R1). | A punch near IST midnight is filed under the wrong `date`; overnight shifts never shift to the previous day. Stored instant carries sub-second noise. | `from_epoch_ms` (naive UTC, truncated to whole seconds); `attendance_date()` applies R1 including the overnight rule. |
| 9 | `punch_in` | Check-then-insert duplicate guard (`find_one` then `insert`) is race-prone; two concurrent punch-ins for the same day can both insert. | Parallel identical punch-ins: both 201 (two records for one day). | Rely on the unique `(emp_code, date)` index; catch `DuplicateKeyError` -> 409. Verified: 12 parallel punch-ins -> one 201, eleven 409. |
| 10 | `punch_in` | Leaks an `id` field (`doc["id"] = str(inserted_id)`) that is not in the contract (and exposes the ObjectId). | Response contains `id`, which the schema does not allow. | Removed; response is built by `serialize_attendance` with only contract fields. |
| 11 | `punch_in` | Accepts any `status` string (`status: str = "PRESENT"`), so `ABSENT`/`LEAVE`/garbage are accepted at punch-in. | `POST ...punch-in {"status":"ABSENT"}` succeeds; contract allows only presence statuses. | Pydantic validator restricts to `PRESENT`/`WFH`/`ON_DUTY`; `punched_at` validated as true epoch ms (rejects seconds/floats/strings/out-of-range -> 422). |
| 12 | `list_attendance` | `list(db.attendance_logs.find(q))` loads the **entire** filtered collection into Python, then sorts and slices in memory — fails the ~100k requirement. Sorts only by `date` (no `emp_code` tiebreak). | On 100k docs the endpoint is slow / memory-heavy; order of same-date rows is unstable. | Do filter + `sort([date desc, emp_code asc])` + `skip` + `limit` + `count_documents` in MongoDB, backed by the `date_emp` index. |
| 13 | `list_attendance` | No `date_from > date_to` validation (contract: 422). Builds `q["date"]` as `{}` even when both are None in some paths; emits `id` from `_id`. | `date_from=2026-07-10&date_to=2026-07-01` returns 200 with empty results instead of 422. | Added the 422 check and a shared `build_attendance_query`; serialize via `serialize_attendance` (no `_id`/`id`). |
| 14 | `health` | Always returns `{"status":"ok"}` without touching MongoDB, so it reports healthy even when the database is down (contract: 503 when the ping fails). | Stop MongoDB: `/health` still returns 200. The grader's readiness probe would be misled. | Run `db.command("ping")`; return 503 on `PyMongoError`. |
| 15 | Module load | `MongoClient(...)` with no `tz_aware` setting returns naive datetimes in one place while helpers created aware ones elsewhere — inconsistent clocks. The connection is also created at import with no index creation. | Mixed naive/aware comparisons raise `TypeError` under some inputs. Indexes never exist, so every query is a COLLSCAN. | One consistent naive-UTC convention everywhere (`to_epoch_ms`/`from_epoch_ms`); indexes created idempotently in the FastAPI `lifespan` startup. |

## Looked at and deliberately kept

- **Reading `MONGO_URI`/`MONGO_DB` with defaults.** The starter's `os.getenv(..., default)` pattern is fine and matches the contract (real env vars win because `load_dotenv()` does not override them). Kept, with the defaults pointing at a local MongoDB.
- **Single `MongoClient` at module scope.** PyMongo's client is thread-safe and pools connections, so one shared client is correct for a concurrent server. Kept (not a defect).
- **Storing calendar dates/shift times as plain strings.** This is intentional per DATA_MODEL.md (a date is not an instant). I kept string comparisons for date-range filters, which also sort correctly because `YYYY-MM-DD` is lexicographically ordered.
